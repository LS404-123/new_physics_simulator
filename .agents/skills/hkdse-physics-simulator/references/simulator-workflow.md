## 三段式 storyboard

| 階段 | 學生行動 | 畫面必須顯示 | 教師／系統提示 |
|---|---|---|---|
| 定向／預測／計劃 | 預測結果、選擇裝置或計劃量度 | 目標、初始狀態、已知條件和可選操作 | 「你準備改變、量度和保持不變的是甚麼？」 |
| 操作／量度／記錄 | 操作模擬、讀取儀器並記錄觀察或數據 | 可見物理變化、儀器反應和學生的原始記錄 | 「這個讀數應記在哪一欄？單位和精度是否合適？」 |
| 處理／解釋／驗證 | 計算、繪圖、比較、作結論或評估方法 | 學生結果、物理關係及針對錯誤的回饋 | 「數據支持甚麼結論？證據是甚麼？」 |

三段名稱是共用骨架，不是固定頁面文案：

- 概念或誤解活動可呈現為「預測 → 操控 → 解釋」。
- 實驗技能活動可呈現為「設置 → 量度及記錄 → 分析及評估」。
- 純數據處理活動可由一組已提供的原始數據開始，毋須虛構儀器操作。

## 實驗技能與數據處理的可重用模式

只選擇與學習目標相關的步驟，不要把每個模擬器變成完整虛擬實驗室。

### 實驗操作

- 讓學生選擇或調整真正影響量度的裝置、位置、量程或控制變量。
- 讀數畫面要足以練習視差、最小分度、零點或穩定讀數等指定技能；若這些不是目標，直接提供清楚讀數。
- 錯誤操作要產生合理後果或具體回饋，不只顯示「錯誤」。

### 記錄及處理

- 以原始讀數開始，讓學生把物理量與單位放在表格欄目標題，並以合適精度記錄。
- 只有在需要時加入重複讀數、平均值或衍生量；不要製造無助於結論的計算。
- 若繪圖是目標，讓學生選軸、刻度和描點；最佳擬合線、斜率三角形或截距可在學生嘗試後提供檢查。
- 保留原始數據、學生處理結果與示範結果，讓回饋能指出錯在讀數、記錄、計算、繪圖還是解釋。

### 分析及評估

- 要求結論引用數據特徵，例如趨勢、斜率、截距或散佈，而不是只選一句預設答案。
- 若目標涉及誤差或改良，回饋要連接「問題 → 對結果的影響 → 具體改良」；避免接受空泛的「提高準確度」。
- 模擬器不取代真實實驗中的安全、器材手感和不可預測情況；交付時說明它實際練習了哪些技能。

## 溫度計校準的可重用模式

這是「校準／測量」類活動的具體例子，不是所有模擬都必須照搬。

### 階段 1：觀察固定點

- 在標準大氣壓下準備冰水混合物和純水沸騰情境。
- 溫度計先顯示沒有攝氏意義的原始讀數，例如冰水讀到 20、沸水讀到 120。
- 問學生：「冰正在融化，這個 20 是否代表 20°C？」
- 顯示熱平衡：液柱放入後移動，等待後才穩定。

### 階段 2：建立刻度

- 學生在冰水液柱位置標記 0°C，在沸水液柱位置標記 100°C。
- 顯示「液柱位置沒有改變，只有刻度的物理意義被建立」的前後對照。
- 將兩固定點之間分成相等間隔；數學比例可放在可展開的補充區，不要在觀察前先展示。

### 階段 3：測量未知水樣

- 先隱藏真實溫度，要求學生預測並把溫度計放入水樣。
- 等液柱穩定後，同時保留「原始讀數」和「校準後攝氏讀數」兩張卡。
- 只有學生完成預測後才啟用「顯示校準後讀數」。
- 結果要清楚指出：原始讀數 70 不是 70°C；在該校準關係下，它代表 50°C。

## iPad Air wireframe

### 無捲動版面規則

頁面內容必須集中在單一 viewport 內；「不捲動」不是把內容剪掉，而是把資訊分級後放進固定的版面預算：

- 頂部：課題名稱、目前階段、重設，保持單行。
- 中央主要區：大型模擬場景，保留物體、液柱、向量或圖表的可見變化。
- 中央側欄：下一個操作、關鍵控制、原始讀數和校準／測量結果。
- 次要內容：短提示或數學補充使用折疊區；不要讓長篇文字把主要場景推到 viewport 外。
- 橫向和直向都不能依賴 body scroll；直向時可由左右欄改為上下欄，但關鍵讀數仍要在同一畫面看見。

CSS 方向：使用 `min-height: 100svh`、`min-height: 0`、`overflow: hidden`（只在已確認內容完整可見時）和 `clamp()` 控制間距及字體。若在目標 viewport 出現捲軸，應刪減裝飾、縮短文案或重排區域，而不是縮小到無法閱讀。

```text
┌──────────────────────────────────────────────┐
│ 課題名稱                         重新開始     │
├──────────────────────────────────────────────┤
│ ① 觀察固定點   ② 建立關係   ③ 測量未知       │
├───────────────────────────┬──────────────────┤
│                           │ 下一步操作       │
│       大型模擬場景         │ 物理提示         │
│   容器／物體／向量／圖表    │ 原始讀數         │
│                           │ 校準後結果       │
└───────────────────────────┴──────────────────┘
```

直向時將右側欄移到模擬區下方；不要把關鍵讀數移到需要橫向滾動的位置。

## 交付前 QA checklist

- [ ] 初始頁面不用閱讀長篇說明也知道第一個操作。
- [ ] 每個階段都有可見的完成條件。
- [ ] 模擬器要求的學生操作與所選教學目標一致，沒有由介面代辦關鍵技能。
- [ ] 若活動使用預測或示範答案，學生先提交自己的想法或結果。
- [ ] 真實物理量、儀器反應、原始數據、學生結果和示範結果按需要使用不同標籤。
- [ ] 所有數字都有合適單位及精度，圖表的軸不會因自動縮放造成誤解。
- [ ] 表格欄目、重複讀數、平均值、衍生量、圖線、斜率和截距均按實際目標檢查。
- [ ] 在目標 iPad Air viewport 中沒有垂直或水平捲軸，所有控制及關鍵結果都在首屏可見。
- [ ] 橫向及直向版面都不會因 safe area、瀏覽器工具列或折疊內容而剪掉資料。
- [ ] 液柱、物體、向量或圖表在 iPad Air 上不互相遮蓋。
- [ ] 錯誤操作或數據處理會指出具體問題及其物理影響，而不只顯示「錯誤」。
- [ ] 等待熱平衡、穩定讀數或動畫結束的狀態清楚可見。
- [ ] 重設後所有狀態、標籤、答案和預測都回到初始狀態。
- [ ] HTML／JavaScript 語法檢查，以及物理狀態或數據處理的最小邏輯檢查已完成。
