# 熱輻射：淨輻射體與淨吸收體模擬器設計

## 理解摘要

- 對象為 HKDSE 學生；學習困難是未能根據物體與環境的溫度判斷淨熱輻射方向。
- 核心誤解是物體只可以是輻射體或吸收體其中之一。正確概念是物體與環境一直互相輻射，溫差只決定淨傳熱方向。
- 進場預測使用同一件 80°C 薄餅：放在 25°C 房間，以及放入 200°C 焗爐。
- 預測畫面只以文字表達兩個情境，突出環境溫度差異；每題以單選按鈕選擇「淨輻射體」或「淨吸收體」。
- 主模擬使用金屬球。學生自由設定物體初始溫度及環境溫度；開始後環境溫度固定，物體溫度逐步接近環境溫度。
- 關鍵證據是持續存在的雙向輻射、物體放出功率、物體吸收功率，以及兩者相減所得的淨功率。
- 非目標包括傳導、對流、材質比較、表面顏色比較，以及真實焗爐加熱時間預測。

## 假設與非功能要求

- 純前端、離線、單人課堂使用，不儲存或傳送資料，沒有帳戶或私隱資料。
- 固定 1140×768 CSS px、effective scale 1；基準 viewport 不可水平或垂直捲動。
- 目標約 60 fps；`prefers-reduced-motion` 下減少輻射波動畫，但所有數值證據仍然更新。
- 沿用專案原生 HTML、CSS、Canvas 及本機 KaTeX，不加入框架或新依賴。
- 球半徑固定為 0.05 m、面積為 0.0314 m²、發射率為 0.90、熱容量為 55 J K⁻¹；介面只讓學生控制兩個溫度。
- 正式運算使用 Kelvin，介面以攝氏顯示。
- 畫面時間採用固定教學倍率，並標示「加速顯示」，不宣稱等同真實時間。
- 所有動畫、溫度、功率柱及角色判斷由同一模擬狀態產生。

## 最終設計

### 進場預測

進入主模擬前顯示兩張純文字情境卡：

1. 80°C 薄餅放在 **25°C 房間**。
2. 80°C 薄餅放入 **200°C 焗爐**。

每題提供「淨輻射體」及「淨吸收體」兩個互斥選項。兩題均完成後才可進入主模擬；提交時不公布答案，答案亦不帶入主畫面。

### 畫面配置

- 頂部：標題、簡短教學目標及返回目錄。
- 中部左側約 70%：恆溫輻射腔、金屬球、雙向輻射動畫及兩個即時溫度值。
- 中部右側約 30%：三條功率柱、實際 W 數值、淨方向及目前角色判斷。
- 底部：物體初始溫度、環境溫度、開始／暫停及重設。
- 不加入歷史圖表、情境快捷按鈕、材質選擇或速度設定。

### 輻射動畫

- 整個 Canvas 代表環境，不再畫包圍金屬球的外殼；入射光線由 Canvas 四邊隨機位置射向球面。
- 金屬球表面由隨機位置向 Canvas 邊界發出幼身光線段。
- 兩邊各自以隨機時間間隔生成光線；平均生成率由各自輻射功率決定。
- 所有光線段使用相同速度、粗幼及亮度；溫度只改變平均光線數量，避免加入另一個視覺變量。
- 光線段到達另一方後消失，表示能量被吸收。
- 光線段是能量流的教學比喻，不代表逐粒真實光子。

### 三條功率柱

三柱使用同一固定線性比例尺：

1. 物體放出功率，由零向上顯示。
2. 物體吸收功率，由零向上顯示。
3. 淨功率，以中央零線為基準；向上代表淨放熱，向下代表淨吸熱。

柱下同步顯示：

\[
P_\text{net}=P_\text{emit}-P_\text{absorb}
\]

並標示「淨輻射體」、「淨吸收體」或「輻射平衡」。負淨功率會明確標示為物體淨吸熱，而不是「沒有功率」。

### 物理模型

固定面積及發射率下：

\[
P_\text{emit}=\varepsilon\sigma A T_\text{物體}^{4}
\]

\[
P_\text{absorb}=\varepsilon\sigma A T_\text{環境}^{4}
\]

\[
C\frac{dT_\text{物體}}{dt}=P_\text{absorb}-P_\text{emit}
\]

環境是固定溫度的大型熱庫，因此開始後環境溫度不變。物體溫度只會接近環境溫度，不可因數值步進越過環境溫度。

當兩者同溫時，放出與吸收功率相等且非零，雙向輻射動畫繼續，只有淨功率歸零及物體溫度停止改變。

### 操作行為

- 物體初始溫度及環境溫度範圍為 -20°C 至 250°C。
- 調校任何溫度會自動暫停並回到新初始狀態，避免把中途改變條件誤當成自然演化。
- 「開始」依物理模型更新物體溫度；「暫停」凍結物體溫度，但畫面保留當前證據；「重設」回到目前設定的初始溫度。
- 所有輸入使用原生控制，具備清楚標籤、鍵盤操作及可見焦點狀態。

## 決策紀錄

| 決定 | 曾考慮方案 | 理由 |
|---|---|---|
| 用熱薄餅與更熱焗爐作反直覺預測 | 冰塊、凍汽水、桑拿人體 | 「已經很熱仍可淨吸熱」的矛盾最清楚；亦避免人體代謝、出汗及牆溫等額外變量。 |
| 主模擬改用金屬球 | 繼續使用薄餅、抽象方塊 | 金屬球容易表達均勻溫度及周向雙向輻射，亦減少焗爐傳導與對流聯想。 |
| 預測答案不即時公布亦不帶入主畫面 | 即時紅綠批改、主畫面保留預測卡 | 讓學生先以物理證據自行修正判斷，並保持主畫面簡潔。 |
| 左側動畫約 70%、右側功率板約 30% | 平均分配、功率板佔較大比例 | 主要空間留給雙向輻射因果；三柱只需支援定量比較。 |
| 使用兩條正向功率柱及一條零中心淨功率柱 | 三柱全部由底向上、瀑布圖 | 零中心設計直接表達淨放熱、淨吸熱及平衡，避免負功率被誤讀。 |
| 光線以隨機位置及隨機時間生成，溫度只控制平均數量 | 固定順序光線、密集同心波紋、以速度表示溫度 | 隨機發射較接近熱輻射的統計表達，亦避免學生把規律序列誤認為物理機制。 |
| 整個 Canvas 作環境 | 圓形外殼包圍金屬球 | 環境輻射可由畫面四邊任意位置射入，不會誤示存在實體外殼。 |
| 只提供兩個自由溫度控制 | 房間／焗爐快捷按鈕、材質與面積控制 | 直接讓學生找出角色轉換條件，避免非核心變量。 |
| 環境溫度固定、物體溫度動態變化 | 兩者固定、兩者同時變化 | 環境作大型熱庫，能清楚觀察物體趨向輻射平衡。 |
| 原生 Canvas、HTML 控制及 KaTeX | SVG、前端框架、圖表套件 | 現有專案已使用此模式，足以完成動畫與方程，無需新依賴。 |

## 風險與限制

- 真實金屬表面發射率隨材質、粗糙度及氧化狀態改變；本模型固定發射率，只研究溫差。
- 真實房間及焗爐同時存在傳導與對流；本模型刻意只計熱輻射。
- 輻射光線數量是視覺編碼，不是可逐條計數的真實光子模型。
- 教學時間倍率會加快趨近平衡的動畫，因此不可用畫面時間預測實物加熱或冷卻時間。

## 驗收策略

最小可執行物理檢查須驗證：

- 物體較熱時，放出功率較大、淨功率為正、球溫下降。
- 物體較冷時，吸收功率較大、淨功率為負、球溫上升。
- 同溫時，放出與吸收功率相等且非零、淨功率為零。
- 球溫不會越過環境溫度，環境溫度全程不變。
- 攝氏至 Kelvin 轉換及 Stefan–Boltzmann 計算正確。

In-App Browser 驗收須覆蓋：

- 1140×768 無水平或垂直捲動。
- 兩題預測的互斥選擇及進入鎖。
- 兩個溫度控制、開始／暫停及重設。
- 三柱方向、數值、角色標籤及同溫平衡狀態。
- 雙向輻射一直存在，且較熱一方只增加波密度／亮度而不改變速度。
- `prefers-reduced-motion`、鍵盤操作及焦點狀態。
- 目錄卡、最新模擬卡、搜尋、主題篩選、預覽圖及模擬連結。
